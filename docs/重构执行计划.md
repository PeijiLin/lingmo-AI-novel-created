## 0. 现状事实核对（2026-11-15 实查）

| 事实 | 结论 |
|---|---|
| 后端流水线 | `CreationPipelineController` 已就绪：`POST /api/book/create/ai/pipeline`（SSE：`stage`/`content` 混合流）、`POST /pipeline/async`（返回 taskId）、`GET /pipeline/task/{id}`（PENDING/RUNNING/COMPLETED/FAILED + totalTokens/elapsedMs/degraded） |
| SSE 协议 | `stage` 事件 data 为 JSON：`{code, status, index, total, round, degraded, usage:{stages,totalTokens,elapsedMs}, error}`，code ∈ PLANNING/WRITING/CRITIC/POLISHING/COMPLETED/FAILED，status ∈ STARTED/REVISION/COMPLETED/FAILED；`content` 事件 data：`{"text":"…"}`。**没有独立 revision/error 事件类型**——REVISION/FAILED 是 stage 事件的 status 取值，前端解析按此实现 |
| 三套 HTTP | `api/core/OpenAPI.ts` 硬编码 `http://localhost:5173/api`；`axiosInstance.ts`（40101 刷新后**不重放原请求**，丢请求缺陷坐实）；`streamPost.ts` 硬编码 `/api` 前缀 |
| `textToTiptapDoc` | `replace(/\s+/g,' ')` 压扁全部段落——段落丢失缺陷坐实，需按行拆段 |
| 排行/发布/阅读+1 | 后端 `BookInfo` 有 `visitCount` 无发布态字段；榜单可先用 `POST /book/page` 按 visitCount 排序兜底；发布按钮对接预留端点、失败优雅降级 |
| **后端路径陷阱** | `server.servlet.context-path=/api` 且 AI/角色卡控制器自带 `/api` 前缀 → 真实路径 `/api/api/book/create/ai/*`、`/api/api/character-card/*`（旧前端两套调用均印证）；`pageBookList` 仅按 createTime 倒序，`sort` 字段未生效 |
| **后端缺陷①** | `UserController.refreshToken` 把 `refresh_token` 字段误存为带 `refresh_token:` 前缀的 Redis key（`map.put("refresh_token", newRefreshTokenKey)`）→ 二次刷新必失效；前端已做 `normalizeRefreshToken` 剥前缀防御，**后端待修** |
| **后端缺陷②（缺口）** | 全后端**无建书接口**（`book_info` 由种子数据入库）→「新建作品」前端预留 `POST /book/create`，失败降级提示；发布二态/榜单/阅读+1 同为预留端点 |
| 字体 | 霞鹜文楷仅 `font-family` 引用无实际加载（静默回退）；本次补 CDN woff2（unicode-range 分片即按需子集）+ 本地字体栈兜底 |
| 工程底座 | 非 git 仓库、零测试、教学注释遗留 |

## 1. 目标架构（与规范 5.1 一致）

```
src/
  api/            # 手写类型化客户端：auth/books/chapters/knowledge/shelf/reading/pipeline + types.ts
  assets/         # 字体声明、静态资源
  components/
    ui/           # shadcn-vue 风格基础件（reka-ui 无头 + cva + 纸墨 tokens）
    base/         # 业务签名件：朱批旁注 / 章节树 / 稿纸编辑器 / 书卷卡片 / 墨线进度 / kb/*
  composables/    # useAuth / useChapters / useAiCreation / useToast
  layouts/        # AppShell（门户壳）/ CreationShell（工作台壳）/ ReadingShell（阅读壳）
  router/         # 全登录守卫（除 /login /register /welcome）
  stores/         # user
  styles/         # tokens.css + base.css
  utils/          # http.ts / sse.ts / tiptap.ts / token.ts / cn.ts
  views/
```

纪律：业务代码一律经 `components/ui/`、`components/base/` 引用；视觉一律取 tokens；`api/` 全部走 `utils/http.ts` 单实例，**全仓库仅此一条 HTTP 通路**（SSE 走 `utils/sse.ts`，共用 token 与 base 解析）。

## 3. 关键实现决策（执行中锁定）

| # | 决策 | 理由 |
|---|---|---|
| D1 | HTTP 用 fetch 不用 axios | 单飞刷新/重放天然可测（工厂注入），阶段 6 可整删 axios 依赖；规范只要求"单实例"，未限定 axios |
| D2 | SSE 协议按后端实况实现 | stage 事件 status 携带 REVISION/FAILED，无独立 revision/error 事件；`[DONE]` 兼容处理；**不虚构协议** |
| D3 | api 层手写不重跑 codegen | 后端 OpenAPI 需起服务才能生成；手写类型化客户端立即可用且无硬编码 base；规范意图是"类型化 + 收敛"，生成工具待后端可起时再回补 |
| D4 | 绞杀者迁移 | 13 个旧页面不可能一次重写；每提交可构建可演示，风险分段释放 |
| D5 | 发布/榜单/阅读+1 三项后端缺口 | 前端全量实现 UI 与调用，端点未就绪时优雅降级（明确 toast 提示），不阻塞主线；后端补充属 platform-v2 仓库工作，另行安排 |
| D6 | 字体走 CDN woff2（unicode-range 分片）| 等效"按需子集化"，离线有本地字体栈兜底，不引入构建期子集工具链 |
| D7 | 朱批 = decoration 标记 + Vue 浮动层 | ProseMirror decoration 打锚点类名（不入文档数据），浮动卡由 `coordsAtPos` 定位，采纳时才真正改文档——与"审阅不污染稿纸"语义一致 |

## 4. 风险与止损

- **R1 流水线时长**：REFINED/PRECISE 单次可能数分钟——SSE 用**空闲超时**（默认 90s 无事件熔断）而非全程超时；提供 abort 与"转异步任务"双通道。
- **R2 旧新并存期样式冲突**：旧页面 tailwind 灰阶 + 新 tokens 并存不冲突（utility 原子类各自独立）；`main.css` 只做入口，不动旧页面依赖的全局骨架。
- **R3 md 水印混入提交**：每次涉及 md 的提交，原子完成「去水印 + add」（平台对 md 外部写盘会回写 AIGC 水印）。
- **R4 BOM**：写盘工具可能带 UTF-8 BOM，每批新文件提交前字节级检查（仓库源文件无 BOM）。
